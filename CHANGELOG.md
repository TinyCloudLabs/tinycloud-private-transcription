# Changelog

## Unreleased

- TC-2119: ptx-batch drops a region whose whole returned text is chat-assistant boilerplate (for example "Thank you for your question. However, I'm not sure what you're referring to. Could you please provide more context…"), so an audio-LLM answer is not published as speech. Only short text made entirely of assistant phrases is dropped; speech that merely contains a phrase is kept. A job whose regions are all dropped ends `no_speech`. New log event `batch_region_ungrounded` (`dropped_regions`, count only, no text) is allowlisted in the log shipper; the embedded Vector config in `infra/dstack-batch/app-compose.yaml` changes, so this needs a ptx-batch CVM redeploy.
- TC-2084: batch jobs wait instead of failing when the transcription provider refuses for billing, quota or key reasons. 402, 401, 403 (and 429 beyond the consecutive cap) release the job to `queued` with a durable not-before (backoff 1, 2, 5, 10, 30 min, then every 30 min, up to 24 h from the first block, then `provider_unavailable`); no retry counter is consumed and the upload is kept. The job status carries `provider_delayed: true` while it waits. New log events `batch_provider_blocked` (`http_status`, `reason`) and `batch_provider_recovered` (`delayed_jobs`) are allowlisted in the log shipper. Ambiguous outcomes (5xx, timeout, reset) keep the no-retry rule; 404 stays terminal. Migration `0028` adds the additive table `transcription_provider_blocks`.
- Dev stack (`infra/dstack`): optional, digest-pinned debug sidecars: key-only SSH through the dstack gateway (`debug-ssh`; its one public key is inlined in the measured compose, placeholder `REPLACE_AT_DEPLOY` refuses to start), a Vector log shipper to the Better Stack source `ptx-dev` that ships only an allowlist of containers (meeting bots, `meeting-api`, `gateway`, `api`, `worker`, `probe`, `debug-ssh`; `debug-log-shipper`), and an on-demand read-only status probe (`profiles: ["probe"]`). A misconfigured `debug-ssh` refuses to start and restarts in a back-off loop; `debug-log-shipper` without a token logs one line and idles. `infra/dstack/deploy-ptx-dev.sh` updates the CVM only while it runs the pinned production OS image `dstack-0.5.12`, re-checks it by CVM id after the deploy and after the `allowed_envs` sync, and exits non-zero on any failure. See `infra/dstack/DEBUG.md`.
- TC-922: batch uploads advertise nominal three-hour support (`10800` seconds) with an inclusive raw ffprobe ceiling of `11101` seconds and a shared `186496800`-byte cap. Reject over-ceiling raw duration before rounding, align Bun's body limit, and retain the full accepted tail in worker decode. Default reserved/daily byte budgets become `1864968000`/`559490400`; processing/upload/PUT deadlines and provider behavior are unchanged. Long-recording validation scope is MP3/AAC only; WAV remains byte-capped. See [evidence and caveats](docs/tc-922-validation.md).
- TC-1093: diarized batch jobs retain ordinary VAD fallback coverage even when quiet detection's peak gate misses or quiet mode is disabled. Known speaker turns remain intact; newly covered audio uses the existing conservative unknown/sliver attribution, without duplicate audio or requests over 30 seconds.
- Apply the existing floor-coverage bound to final diarized turns before persisting regions or calling the provider. Primary VAD coverage can repair diarizer omissions; an insufficient final union fails `processing_failed` instead of publishing a partial transcript. Result mode/fallback and drop metrics describe the selected mode and final coverage, and remain atomic with saved regions across re-claims.
- Retain deterministic short/fail-closed regressions and a manual public-AMI pre-deploy HTTP API/worker replay in `test/support/diarized-replay.ts`. The replay uses the shipped native diarizer and validates every dispatched WAV against captured worker PCM; its loopback provider returns deterministic text, so it does not measure ASR accuracy or hallucinations. The short bypass existed at both `7e54bcd2` and #105; this is not a claim that #105 caused it.
