# Changelog

## Unreleased

### Main
- ptx-dev's bot janitor now also removes old bot images by default (`BOT_JANITOR_PRUNE_IMAGES` defaults to `true`; `false` turns it off). It removes only bot images older than the pinned bot image that no container uses; the pinned image and newer ones are kept. Details: TC-2181
- TC-3653: A recording still processing 72 hours after upload now expires too, even if it never waited on the provider. A job claimed just before the deadline previously kept its audio until the 4-hour processing ceiling (up to 76 hours after upload). The sweep fails it `processing_timeout`, fences out the worker and deletes the audio.
- TC-3490: destructive-migration gate for ptx-batch and ptx-dev. CI (`bun scripts/migration-gate.ts check`) fails a migration from 0032 on that drops, truncates, deletes, updates, renames, changes a column type or sets NOT NULL unless it is marked `-- destructive: TC-NNNN`. Deploys (`deploy-batch.yml` before the drain, `infra/dstack/deploy-ptx-dev.sh` before any change) read the live api image commit and refuse a pinned image that adds a destructive or marked migration, unless `destructive_migration_ack` / `DESTRUCTIVE_MIGRATION_ACK` names exactly those migrations (its own GO). ptx-batch keeps no database backup: a lost database recovers from the sealed config at boot (runbook "Recovering from a lost database"; `test/integration/batch-empty-db-recovery.test.ts`). Keys made with `create-key` are not rebuilt.
- TC-2743: A recording still queued 72 hours after upload expires, even if transcription never started. The cleanup sweep deletes its audio and retries any deletion that fails.
- TC-3136: `DELETE /v1/meetings/{id}` now purges the capture provider's copy (Vexa audio, video, transcript and derived artifacts, including attributed-audio and signal-tape objects) and verifies it by read-back before the meeting row is deleted. Unconfirmed purges answer retryable `503 provider_unavailable` and keep the row; the earlier paths that only logged a Vexa 409 or trusted an already-admitted delete are gone. Vexa's delete addresses a meeting by code and one Vexa user serves every project, so it is sent only when Vexa resolves the code to a row recorded for this meeting (otherwise `provider_row_mismatch` / `provider_row_unlinked`, nothing sent, row kept); the code-based transcript fallback is removed. What Vexa held (row ids, owner, recording ids) is saved on the meeting row (`meetings.deletion_snapshot`, migration 0030) and reused on retries, so objects are re-checked after a store failure. An unset `VEXA_MINIO_ENDPOINT` or an unprovisioned credential fails the delete closed instead of skipping. Vexa keeps a content-free tombstone row. The api service now carries the retention MinIO credential, which needs a deploy. The 14-day retention sweep is unchanged and stays dry-run. Details: TC-3136
- TC-3136 (race fix): the check "Vexa resolves this code to my row" and the code-addressed Vexa delete now run under a Postgres advisory lock per platform + meeting code that every bot start for that code also takes, so a new meeting on a recurring code cannot start between the check and the delete and be purged. A meeting is reachable by its stored provider code and the code its URL names; both are locked (sorted, all or none). The `stopBot` before the delete of a still-running meeting runs inside the same lock. A delete that finds a code busy aborts with a retryable `503 provider_unavailable` having sent nothing; a start waits for it. Other code-addressed stops stay outside the lock: a user or API stop (`stopMeeting`), the cleanup stop for a meeting cancelled while its bot was being dispatched, and the join-deadline stop.
- TC-3136 (deploy): the api service now waits for `minio-init` (`service_completed_successfully`), so the first delete after a first boot finds the `ptx-retention` user and its secret file. The retention user's `s3:ListBucket` is scoped with an `s3:prefix` condition to `recordings/*`, `attributed-audio/*` and `signal/*` (it was bucket-wide); `s3:DeleteObject` already covered only those. Checked against the pinned MinIO release with the real object-store client: list under each prefix and delete there succeed; a bucket-wide list, another prefix, and a delete outside the prefixes are denied. Applied the next time `minio-init` runs (every boot reapplies the policy).

- TC-2128: retained-recording Whisper transcription bounds each encoded WAV to 580 seconds, including a two-second shared seam, with one FFmpeg decode and sample views. Quiet cuts cover the full recording; segment offsets are restored to the recording clock and duplicate boundary words are removed only where their audio spans overlap. A seam consumes one matching suffix/prefix across segment boundaries: a previous occurrence cannot erase multiple incoming repetitions, and differing segment partitions do not leave duplicate seam words. A failed upload still fails the attempt instead of publishing a transcript with a hole. Oversized attributed/recording windows retain the existing sub-30-second timestamp convention, including padding in the limit. Model selection and defaults are unchanged by this change; local controlled ASR verification does not establish real-Whisper speech quality or authorize a default switch.
- TC-2148: the meeting transcript path drops Whisper sound captions too. `hallucinationReason` returns the new reason `caption` when the whole text of a piece is one wrapped sound or music caption (`*Piano music*`, `[Music]`, `(applause)`, `♪ music ♪`), using the same closed list as ptx-batch (TC-2144). It applies to recording gap-fill windows and pieces, retained-recording recovery chunks and attributed batches, and is not gated on a model name because the meeting path uses Whisper only since TC-2118. A dropped caption is a listed gap (recovery: the transcript is marked `partial`), as for any other dropped text over possible speech; a caption inside longer text, unlisted bracketed text and a bare `Music` are kept. Checked after every existing rule, so no existing result changes. No new log event and no Vector or log-shipper change (`reason` is not a shipped enum field on the meeting path). Takes effect on the next API and worker deploy.
- TC-2144: for Whisper-class models ptx-batch also drops a region whose whole text is one wrapped sound or music caption (`*Piano music*`, `[Music]`, `(applause)`, `♪ music ♪`, `[BLANK_AUDIO]`), as no speech. The match is a closed list of sound words (at most 40 characters inside the wrapper); a caption inside longer text (`[laughs] and then he left`), unlisted bracketed text and a bare `Music` are kept. Counted by the existing `batch region ungrounded` event; no new event, no Vector change. Voxtral is unchanged. Takes effect on the next ptx-batch deploy (drain first).
- TC-2118: no audio or chat LLM transcribes meeting speech. The attributed Google Meet path used `TINFOIL_ATTRIBUTED_FALLBACK_MODEL` (`voxtral-small-24b`) for a batch, or recording gap-fill chunk, after two empty Whisper results, and an assistant-style reply to unclear audio ("Thank you for your question. However, I'm not sure what you're referring to...") was published as speech. The setting, the model switch and `source: "fallback"` output are removed (no replacement flag). A batch Whisper answers empty twice now stops retrying and is gap-filled from the retained recording by Whisper, then listed in `gaps`; nothing is invented. `TINFOIL_ATTRIBUTED_MODEL` now defaults to `whisper-large-v3-turbo` instead of the recovery model. Last-line guard (`src/domain/hallucination.ts`, every provider and audio length): text that is wholly assistant boilerplate (two or more sentences, all courtesy or reply sentences, at least one reply sentence) is rejected, including a reply split across Whisper segments; untimed text is also rejected when its speaking rate is implausible for the voiced seconds. Results already stored by the fallback model are published as gaps, not text. The `infra/dstack` compose drops the variable; ptx-batch is unchanged.
- TC-2118: retained-recording recovery (`TINFOIL_MODEL`, used when Vexa lost a material tail) now defaults to `whisper-large-v3-turbo` instead of `voxtral-small-24b`, in `config.ts`, `infra/dstack/app-compose.yaml` (api and worker) and both `.env.example` files. Its text now passes the same last-line guard as the attributed path: a chunk that is an assistant-style reply, a loop, or an implausible speaking rate for its voiced seconds is dropped and the transcript is marked `partial`; if every chunk is dropped the recovery fails with no words, as for an empty answer. A sealed `TINFOIL_MODEL` overrides the compose default: remove it, or set it to a Whisper model. `EVAL_MODELS` shadow runs and ptx-batch (`BATCH_TINFOIL_MODEL`) are unchanged.

- TC-2084: batch jobs wait instead of failing when the transcription provider refuses for billing, quota or key reasons. 401, 402, 403 and 429 beyond the consecutive cap release the job to `queued` with a durable not-before; provably-unsent outages enter the same wait after five immediate attempts. Backoff is 1, 2, 5, 10, 30, then 60 minutes and repeats hourly, with an absolute 72 h deadline from the earlier of upload or first block; the sweeper also fails overdue queued jobs that cannot be claimed, and a woken wait still processing at the deadline. Uploaded audio is kept while retrying and deleted on completion or terminal failure; partial region text is cleared at terminal failure, while completed transcript text retains its separate 24 h expiry. Ambiguous 5xx, timeout and reset outcomes are never retried; 404 stays terminal. Jobs expose `provider_delayed: true` while waiting. `batch_provider_blocked` and `batch_provider_recovered` remain allowlisted. Migration `0028` adds the provider-block table; `0031` allows a null `last_status` for provably-unsent waits. Details: TC-2084
